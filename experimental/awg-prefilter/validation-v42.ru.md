# V42. Измерение UDP без захвата пакетов

[English](validation-v42.md) | Русский

Приёмник стенда теперь выдаёт пропущенные номера по секундам расписания отправителя. Он уже отмечал каждый полученный номер. Новый отчёт строится после прогона по этим отметкам, поэтому не добавляет работы при обработке пакетов. Захват внутреннего UDP по-прежнему нужен для отметок времени и поиска конкретного перехода, на котором пакет пропал. Для подсчёта доставки достаточно показаний приёмника.

## Что сравнили

На четырёх VM Debian 13 под QEMU/WHPX было по одному vCPU и 1024 МиБ. Во всех прогонах генератор подавал 25 000 шумовых пакетов/с с 16 IP порциями до 4096 пакетов. От B к клиенту шло 6000 полезных UDP-пакетов/с по 1200 байт. Между A и B была задержка 150 ± 30 мс в каждую сторону. Клиент трижды менял IP и NAT-порт. При первой смене помощник A получил SIGKILL. Отправитель, приёмник, профили, правила фильтра и размеры очередей были одинаковыми во всех четырёх прогонах.

Порядок прогонов был таким: с захватом, без захвата, без захвата, с захватом. В прогонах без UDP-захвата доставку измеряли по отправителю и приёмнику. Захват ICMP, короткий захват на коммутаторе, счётчики шума по источникам и сбор метрик VM работали в обоих режимах. Для зачёта стенд должен был принять 1 750 000 шумовых пакетов с ожидаемых адресов, выдержать заданные скорости и пройти без потерь коммутатора. Для прогонов с захватом также сверяли его полноту.

| Режим | Зачтён | Потери UDP | Потери коммутатора | Пропало ping | Максимальный RTT, мс |
|---|---|---:|---:|---:|---:|
| Захват / A | нет | 41309 | 158959 | 69 | исключён |
| Приёмник / A | да | 0 | 0 | 0 | 1244.017 |
| Приёмник / B | да | 0 | 0 | 0 | 1306.374 |
| Захват / B | да | 0 | 0 | 0 | 1265.900 |

## Где произошёл сбой

В первом прогоне с захватом коммутатор потерял 158 959 кадров. Из них 155 829 пришлось на выход к A и 3130 на выход к клиенту. Счётчик RX на A не рос около 4,77 с, хотя сбор метрик продолжался. NFQUEUE и C не сообщили о потерях из-за своих лимитов. На A дошло 1 627 120 из 1 750 000 шумовых пакетов. Прогон исключён из оценки фильтра. При этом номера из захвата и показания приёмника совпали, в том числе по 41 309 полезным UDP-пакетам, не дошедшим до приложения.

В обоих прогонах без захвата доставлены все 720 000 полезных пакетов и 200 ответов ping. Худший RTT составил 1,306 с. Повтор с захватом тоже прошёл без потерь. Средняя загрузка клиентской VM составила 11,5–11,6% без захвата и 17,8% в корректном прогоне с захватом. На B получились 32,4–32,6% и 37,6% соответственно. Для подсчёта доставки достаточно облегчённого режима стенда. Эта серия не устанавливает причину остановки приёма в QEMU и не доказывает, что захват её вызывает.

Секунды в отчёте приёмника рассчитаны по расписанию отправки. Точных времён доставки и пути каждого пропавшего пакета в них нет. Для таких вопросов по-прежнему нужен отдельный захват. Параметры смены адреса, лимиты очередей и код VPN не менялись.

## Проверка

Обновлённый пробник собирается с предупреждениями как ошибками и проходит самотест на B и на клиентской VM. После испытаний восстановили обычный DNAT и исходный B. Оба исходных профиля подключились, VM выключены.
