# Сохранение истории между последовательными сменами NAT

[English](validation-v25.md) | Русский

Даты измерений в UTC: 2026-11-14. В семи финальных
прогонах все 2 535 070 полезных UDP-датаграмм дошли до получателя.
Это подтверждено полными захватами с обеих сторон туннеля.
Обычные пробы дали 1400/1400 ответов вовремя.
Частые пробы: 693/700 вовремя,
7 поздно, 700/700 в захватах.
Секундный дедлайн прежний. Это результаты конкретных проверок,
без гарантии смены адреса без потерь в любых условиях.

В трёх парных случаях двух смен потери UDP изменились с 1048
до 0 для IP, с 564 до 0
для порта и с 1071 до 0 для обоих.
См. [данные](results-v25.json) и [v24](validation-v24.ru.md).
Опция экспериментальная и по умолчанию выключена. Действующие серверы,
VPN пользователя и сеть Windows не менялись. В ходе лабораторной работы
публикации на GitHub не было.

## Что показали контрольные варианты

V24 может терять раннее окно восстановления, когда следующая проверенная
смена создаёт более новый замороженный снимок. Возраст отсутствующих пакетов
также пересекает границу конечного окна повторов клиента. Старые захваты
не показывают внутреннюю причину отказа клиента; один возраст не доказывает
отбрасывание его фильтром.

`fast` сокращает паузу на клиента до 500 мс при прежних снимках. Он всё ещё
теряет UDP-пакеты: 785 в одном прогоне и 831 в другом. `refresh` сохраняет первый выбор, добавляет
новые ответы при следующей смене и увеличивает предел числа пакетов в прежнем
бюджете байтов. В двух прогонах потерь UDP нет, но четыре и пять частых ответов
опоздали. `early` сокращает паузу до 250 мс. Две смены и три смены через
100 мс проходят, но три смены через 250 мс теряют 2466 UDP-датаграмм.
Журнал показывает повтор на второй путь и новый выбор из кольца для третьего,
когда прежний снимок уже освобождён.

Финальная правка сохраняет снимок после каждой попытки до исходного срока.
Следующая свежая проверенная смена разрешает новую попытку и добавляет
более новые подходящие ответы. Трафик без смены адреса не разрешает повтор.

## Ограничения и владение данными

Обычное кольцо прежнее: 8192 пакета / 8 МиБ / выбор моложе 500 мс.
Для всех сохранённых снимков действует общий предел: 16 клиентов,
8192 пакета и 2 МиБ шифротекста.
На одну попытку тоже не более 8192 пакетов и 2 МиБ. Предел числа пакетов
увеличен с 4096; бюджеты байтов шифротекста прежние. Локальный номер вставки
позволяет добавить только более новые записи кольца. Данные первого выбора
переиспользуются без второго копирования; дополнения копируются один раз.

Каждый снимок истекает через 1100 мс после создания. Смена назначения,
дополнение и отправка не продлевают срок. Прежняя очистка через 100 мс
освобождает неактивные записи; новых таймеров и обработчиков на клиента нет.
Минимальный интервал равен 250 мс на клиента и суммарно для непустых попыток,
одновременно выполняется одна отправка. Общий допуск прежний, но теперь один клиент
может использовать его целиком.

Нужны свежий transport-пакет с проверенной подлинностью, текущий ключ
и допустимый внутренний адрес. Проверяются состояние клиента/устройства,
разрешение roaming и актуальное назначение; каждая пачка снова проверяет
ключ и назначение. Хранятся шифротекст, хеш открытого ключа и скалярные поля
эпохи/порядка/адреса. Открытых данных, ключей сессии и ссылок на клиента
или пару ключей нет. Уже переданные сети пакеты отозвать нельзя.
Подтверждённый путь может исчезнуть до прихода ответов.

## Сравнение в одинаковых VM и модели NAT

Четыре новые COW-VM Debian 13 с ядром 6.12.116 работают под QEMU11.1.3/WHPX,
по одному vCPU и 1024 МиБ. Квот и порога CPU нет. Шум: 25 000 датаграмм/с
на 70 секунд, один IPv4 и 64 порта, пачки по 4096 пакетов. В данных шума
снятый transport-префикс с изменённым шифротекстом. Полезный обратный UDP
запрашивает 6000 датаграмм приложения/с, 128 байт, на 60 секунд. Измеритель
тот же отдельный iperf3 3.18 с допуском стартовых перестановок из v22-v24;
фактические длительности и числа отправителя сохранены.

RTT 300 мс: задержка netem по 150 мс и нормальный джиттер по 30 мс в каждом
направлении A-B, включая mTLS. Очереди по 16 384 пакета, случайных потерь
не задано. Двадцать физических ping проверяют каждую настройку. Меняется
только NAT одноразового шлюза. Профили, ключи, listen-порты и нативные
бинарники клиентов прежние. Один профиль перемещается, второй отправляет
контрольные пробы без смены адреса.

У всех вариантов исправленная модель INPUT шлюза из v24. До подтверждения
conntrack отбрасывается только локальный обратный UDP без отображения NAT.
Корректный обратный DNAT проходит через FORWARD. Изолированный отрицательный
контроль выполнен в v24; здесь он не повторялся. Поведение любого физического
роутера этим не подтверждается.

Полные внутренние захваты считают уникальную доставку UDP, включая GSO/GRO
и короткий служебный хвост. Потери iperf записаны отдельно. Захват не доказывает
потребление приложением. Каждый профиль посылает 100 обычных проб через
500 мс; ещё 100 частых проб идут через 50 мс возле смены. Дедлайн остаётся
секундным; вовремя, поздно и в захвате считаются отдельно.

## Проверки и оставшаяся работа

Финальные исходники прошли 33 Go-теста, два upstream-теста пропущены.
Все Coldwire-тесты device прошли детектор гонок в VM 1 ядро / 1 ГиБ.
Проверены общие бюджеты, сохранённый снимок без разрешения на повтор,
номер вставки, перекрытие/порядок, неизменность срока, текущий ключ/адрес,
конкурентная очистка и две намеренные потери настоящего шифротекста,
восстановленные разными попытками без дублей открытых данных. Семь Python-тестов
прошли в Windows и обоих серверных гостях. Патч воспроизводит файлы в чистых
закреплённых исходниках и отвергает повтор без изменений. Сборки используют
кешированные инструменты и модули офлайн; во время трафика компиляции нет.
У каждого варианта сохранены неизменяемые исходники и хеш бинарника.

До выключения восстановлены штатные бинарник/служба/окружение выхода,
обычный DNAT и исходные NAT/профили; обе нативные пробы прошли. Все четыре
VM, seed и switch выключены; 11 loopback-портов свободны. Родительские диски,
прежние данные и персональные JSON совпали по исходным хешам.

На действующих серверах восстановление пока оставьте выключенным. Высокий
PPS и крупные пакеты могут выйти за окно повторов или бюджет байтов.
Серия смен может продолжаться дольше 1100 мс; один клиент может занять общий
бюджет восстановления. Несколько одновременно перемещающихся клиентов,
физические GUI-клиенты Windows/macOS/Android/iOS, DPI, распределённый шум
и исчерпание состояния не проверялись. Подтверждённый клиент по-прежнему
может вызвать ограниченное усиление без доказательства обратной достижимости.
Повторяющийся шифротекст остаётся видимым и связываемым.
