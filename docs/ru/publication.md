# Подготовка исходников к передаче

[English](../publication.md) | Русский

COLDWIRE опубликован из проверенного дерева исходников с новой историей
Git. Прежний приватный репозиторий и его объекты не переносились.
Лицензия MIT относится к оригинальным скриптам, тестам, документации и оформлению проекта.
Лицензии сторонних компонентов и адресных данных описаны в
[THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).

Передавайте только дерево исходников с готовыми публичными бинарными
пакетами из `dist/`. Исключите папки `private/`, `generated/`, `.venv/`,
профили, ключи, журналы, образы VM и резервные копии.

Передавайте адреса серверов в параметрах запуска. Не вписывайте их
в значения по умолчанию или примеры. Отчёты установки с адресами
и SSH-отпечатками, экспорты профилей и резервные копии храните как закрытые данные.

## Проверка файлов и истории

Обычный коммит с удалением адреса не удаляет его из прежних коммитов.
Если прежняя история содержала сведения об установке, для передачи исходников
предпочтительна новая копия с одним проверенным начальным коммитом.
Не публикуйте старую историю, ветки, теги или `.git` из рабочего каталога.
Уже опубликованные сторонние копии истории такой подготовкой не удаляются.

После проверки содержимого можно получить архив только текущего дерева:

```bash
git archive --format=zip --output=../coldwire-source.zip HEAD
```

Архив не содержит `.git`, но **его содержимое всё равно нужно проверить**:
`git archive` включает закоммиченные файлы, даже если они затем попали в `.gitignore`.
Для отдельного репозитория распакуйте проверенный архив в новую пустую папку:

```bash
git init -b main
git add .
git commit -m "Initial source release"
```

Не копируйте старый `.git` и не добавляйте старые refs. Создание удалённого
репозитория, выдача доступа коллегам и смена публичности выполняются отдельно.
Локальная чистая копия сама по себе не очищает историю исходного GitHub-репозитория.

После переписывания опубликованной истории старые клоны нужно заменить
свежими, не сливать их обратно. GitHub также может сохранять старые объекты
по SHA в кэше; force-push не гарантирует их физическое удаление.
Это отдельно описано в [инструкции GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

## Проверка выпуска

Из корня исходников подготовьте venv оператора и запустите тесты.
Параметр справки настраивает локальную среду без подключения к серверам.

Linux/macOS:

```bash
bash setup.sh --help
.venv/bin/python -m unittest discover -s tests -v
```

Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 --help
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Paramiko нужен для SSH-тестов; без него один тест host keys будет пропущен.
Проверьте синтаксис Bash во всех `servers/*.sh`, локальные ссылки Markdown,
соответствие хешей и чисел JSON документации и офлайн-воспроизведение снимков.
Проверьте дерево и вложенные архивы на реальные доступы, адреса установки
и локальные пути. Ключи в модульных тестах синтетические; они не должны
совпадать с выданными доступами. Сохраняйте лицензии и исходники компонентов
в `dist/awg-native-linux-amd64.tar.gz` и `dist/xray-native-linux-amd64.tar.gz`.
Xray-пакет содержит лицензию и manifest со ссылкой на исходники закреплённой версии.

Поддерживаются Debian 12/13 и Ubuntu 22.04/24.04/26.04 LTS amd64. Результаты проверок
приведены в [отчёте Debian](validation-debian.md), [отчёте LTS](validation-lts.md),
[отчёте трёх режимов на 22.04](validation-protocols.md)
и [раннем отчёте AWG](validation-native.md). Правка документации сама по себе
не означает повторного прохождения полного VM-цикла.

## Первый публичный выпуск

В первом публичном выпуске исполняемые скрипты, тесты, адресные данные,
бинарные пакеты и два JSON были перенесены из проверенного архива без изменений.
В этом выпуске добавлены название, оформление, MIT и английский перевод;
служебные имена не менялись.
Повторно прошли 44/44 unit-теста и офлайн-воспроизведение списков. Для 13 пар
RU/EN проверены команды, контрольные хеши, переключение языка и локальные ссылки.
SVG-шапка отрисована и визуально проверена; встроенный логотип совпадает
с оригинальным PNG. Дерево и вложенные архивы проверены на рабочие доступы,
адреса узлов и личные пути до публикации новой истории.

Полный VM-цикл в этом редакционном этапе не повторялся: его результаты
относятся к неизменённым скриптам из [отчёта протоколов](validation-protocols.md).

## Английский язык по умолчанию и новые LTS

Основные пути документации: `README.md` и `docs/`. Русский перевод находится
в `README.ru.md` и `docs/ru/`; ссылки переключения языка сохранены.
При этом обновлении сохранились команды и схемы прежних 13 языковых пар.
Добавлена четырнадцатая пара с [результатами LTS](validation-lts.md). Готовые
бинарные пакеты, адресные данные, логотип PNG и оба RU JSON не менялись.
В SVG-шапке обновилась подпись платформы. Проверены ссылки, хеши и отсутствие закрытых данных.
47 unit-тестов прошли на Windows и гостевых Python 3.12/3.14. Для поддержки
новых ОС выполнены шесть VM-циклов, перечисленных в отчёте LTS.

10 ноября отдельная [проверка обычной перезагрузки](validation-lts.md#обычные-перезагрузки)
добавила шесть новых VM-циклов и 24 перезагрузки гостя с локально исправленной
тестовой сборкой QEMU/WHPX. VPN-скрипты и готовые пакеты не менялись.

При последующей редактуре английский остался основным языком, русский
перевод сохранён. Для шапки и схемы в README созданы одинаково оформленные SVG
на английском и русском. Скрипты, команды, адресные данные, бинарные пакеты
и оба RU JSON не менялись. Для этих правок документации VM-цикл не повторялся.
