# Установка и управление реле COLDWIRE

[English](../access-panel.md) · [Главная проекта](../../README.ru.md)

## 1. Подготовьте два VPS

Нужны два чистых сервера amd64 с systemd. Поддерживаются Ubuntu 22.04, 24.04 и 26.04 LTS и Debian 12 и 13. У каждого сервера должен быть свой публичный IPv4 и рабочий вход по SSH с правами root или sudo. Для управления и выхода VPN в интернет используется IPv4. Проверьте, что из панели провайдера можно открыть аварийную консоль обоих серверов.

Установщик разворачивает COLDWIRE прямо на обоих серверах, без Docker. На узле B AmneziaWG 3.1 работает как служба systemd.

Если у провайдера есть отдельный межсетевой экран, заранее разрешите следующие подключения. Установщик управляет правилами внутри VPS.

| Узел | Что разрешить у провайдера |
| --- | --- |
| A, вход | Текущий порт SSH с вашего компьютера на время установки. TCP 22222–22253 для управления. UDP 62201 для SPA и UDP 32497 для AmneziaWG. |
| B, выход | Текущий порт SSH с вашего компьютера на время установки. TCP 22222–22253 и UDP 32497 с IPv4 узла A. |

Установщик выбирает свободный SSH-порт из этого диапазона на каждом узле. После проверки нового подключения он закрывает внешний доступ к исходному порту SSH. Когда новый вход заработает, временные правила у провайдера можно убрать. Для восстановления доступа пригодится аварийная консоль.

## 2. Запустите установщик

На компьютере администратора нужны стандартный CPython 3.10 или новее и клиент OpenSSH. В Ubuntu и Debian установите пакеты `python3`, `python3-venv` и `openssh-client`.

Скачайте и распакуйте `COLDWIRE-Access-Panel.zip`. В архиве есть скрипты запуска и исполняемый файл SPA-сервера для Linux. [Последний релиз панели](https://github.com/bgunn9in/coldwire/releases/latest)

В Windows дважды щёлкните по `COLDWIRE-Admin.cmd` в распакованной папке. Скрипт сначала ищет сохранённую установку в этой папке, затем в `%LOCALAPPDATA%\COLDWIRE\access-panel`. Если обе папки пусты, панель предложит **Install COLDWIRE**.

Чтобы открыть конкретную установку, запустите из распакованной папки в PowerShell

```powershell
.\COLDWIRE-Admin.cmd --folder "C:\папка с данными\оператора"
```

В Linux откройте терминал в распакованной папке и выполните

```bash
bash COLDWIRE-Admin.sh
```

Скрипт для Linux сначала ищет сохранённую установку в распакованной папке, затем в `${XDG_DATA_HOME:-$HOME/.local/share}/coldwire/access-panel`. Для другой папки укажите `--folder "/путь к/данным оператора"`.

Выберите **Install COLDWIRE**, введите IPv4, логин и пароль SSH узла A, затем те же данные для B. Если сервер использует другой SSH-порт, допишите к адресу `:порт`. По окончании установки откроется меню управления. Скрипты устанавливают зависимости Python в `.venv`. Установщик запоминает ключи SSH-серверов при первом подключении и отклоняет их подмену при следующих. Если запускаете установку из исходников, на компьютере администратора понадобится Go для сборки SPA-сервера.

Установщик проверяет оба узла, запускает AmneziaWG на B и проверяет реле через A. Затем он применяет правила межсетевого экрана и проверяет новый вход по SSH через SPA и рукопожатие AmneziaWG. На каждом этапе настройки экрана действует трёхминутный таймер отката. Перезагрузка также отменяет неподтверждённый этап.

Когда установщик подтверждает правила, systemd загружает их перед запуском SSH и VPN. На A административный SSH, служба SPA и реле также ждут загрузки правил допуска SPA.

## 3. Подключите первое устройство

1. Установите на устройство COLDWIRE Amnezia VPN. [Инструкция для клиента](https://github.com/bgunn9in/COLDWIRE-amnezia-client/blob/feature/spa-admission/docs/spa.ru.md)
2. Передайте на устройство `private/coldwire-installation/client1.vpn` по закрытому каналу. Импортируйте его через **+** и **Файл с настройками подключения**.
3. Подключитесь и откройте сайт проверки IP, который идёт через VPN. Он должен показать IPv4 узла B. Если включили раздельное туннелирование, сайт, доступный напрямую, должен видеть адрес провайдера. [Списки исключений](lists.md)

## 4. Управляйте профилями

Для входа в панель снова запустите тот же скрипт.

| Пункт меню | Действие |
| --- | --- |
| `1 Status` | Проверяет оба узла и показывает адреса SSH и состояние правил. |
| `2 List users and devices` | Показывает профили и их владельцев. |
| `3 Add device and export profile` | Создаёт профиль AmneziaWG и ключ SPA. Укажите то же имя пользователя, чтобы объединить несколько устройств. |
| `4 Revoke device` | Удаляет устройство из AmneziaWG и отзывает его ключ SPA. |
| `5 SSH to entry` / `6 SSH to exit` | Открывает оболочку через административный SPA. Подключение к B проходит через A. |
| `7 Revoke user and all their devices` | Отзывает все устройства пользователя. |
| `8 Import an AmneziaVPN profile` | Конвертирует готовый профиль AmneziaWG 3.1 и при необходимости выдаёт ключ SPA. |
| `9 Exit migration` | Запускает, проверяет, подтверждает и откатывает перенос B с Docker на systemd. Пункт доступен при пилотном SPA на A и Docker или уже перенесённом AmneziaWG на B. |
| `10 Restore from backup` | Проверяет `.cwbackup`, восстанавливает папку оператора или выгружает файлы для восстановления A и B. Доступен и до установки. |
| `11 Create backup` | Читает оба узла через административный SSH и сохраняет зашифрованную копию вместе с папкой оператора. |

Чтобы сменить ключ устройства, выпустите для того же пользователя новый профиль, проверьте подключение и отзовите старое устройство. Сделайте закрытую резервную копию `private/coldwire-installation/`. В папке хранятся ключи SSH и SPA администратора, отпечатки серверов и выданные профили. Каждому пользователю передавайте только профиль его устройства.

### Импорт профиля AmneziaVPN

Выберите **8** и укажите файл `.vpn`. Устройство из профиля должно быть уже зарегистрировано в AmneziaWG на B. Если оно есть в панели, укажите прежнее имя устройства для повторного экспорта. Если в администраторском экспорте нет клиентских данных, панель попросит прямой клиентский `.vpn` с узла B.

Панель создаст `<устройство>-coldwire.vpn` и сохранит исходный файл и действующие ключи AmneziaWG. В администраторском профиле останутся параметры управления сервером. Для входа по SSH после закрытия портов пользуйтесь панелью COLDWIRE.

### Пилотный SPA на A после переноса B

Откройте существующую установку в панели и выберите **9 Exit migration**. Сценарий проверен на Ubuntu 22.04 amd64 с одним внешним интерфейсом на B, туннельной подсетью IPv4 и отдельным маршрутом `/32` к каждому адресу пира. В папке администратора нужен гостевой экспорт этого сервера `legacy-template.vpn`.

1. В окно работ выберите **2 Start migration**. Панель сохранит конфигурацию на B и включит десятиминутный таймер отката перед переключением UDP-порта на нативную службу.
2. Проверьте SSH через A и трафик через действующий VPN-профиль. Выберите **3 Confirm migration**. Панель проверит свежее рукопожатие и трафик на B, затем обновит `operator.json`.
3. Если проверка не прошла, выберите **4 Roll back**. По истечении срока контейнер восстановит таймер, даже при потере SSH. Состояние видно в **1 Migration status**. Добавляйте и отзывайте устройства после подтверждения или отката.

Docker остаётся доступен для восстановления. Загрузку B с нативной службой и отключение Docker можно проверить в отдельное окно.

После ручного переноса настройте панель так.

Когда B перейдёт с Docker на systemd, установите `pilot_spa` в `true` в файле `operator.json` из папки администратора. В объекте `native_exit` укажите два абсолютных пути на B. В поле `awg` нужен путь к исполняемому файлу, в `config` — к конфигурации, которую читает служба при запуске. Оставьте рабочий гостевой профиль в `legacy-template.vpn`. Панель возьмёт из него параметры подключения для новых профилей.

При добавлении и отзыве панель меняет запись пира по его публичному ключу в файле на B и на работающем интерфейсе. За ключи допуска на A отвечает прежняя служба `coldwire-spa-pilot.service`.

## Создание зашифрованной копии

Откройте нужную установку в панели и выберите **11 Create backup**. Нажмите Enter для сохранения в стандартную папку или введите другой путь на компьютере оператора. Панель прочитает конфигурацию A и B с помощью действующих ключей SPA и SSH. Если меняете правила экрана или переносите B, дождитесь завершения операции.

Панель покажет пути к архиву `.cwbackup` и ключу восстановления. В Windows по умолчанию ключ защищён DPAPI и открывается в профиле, который создал копию. Если планируете восстановление с другого компьютера, выберите переносимый ключ. В Linux панель всегда создаёт переносимый ключ и запрашивает парольную фразу. Храните ключ отдельно от архива, а фразу отдельно от обоих файлов.

Копию можно создать из командной строки.

```powershell
.\COLDWIRE-Admin.cmd backup
```

```sh
bash COLDWIRE-Admin.sh backup
```

Если папка оператора лежит в другом месте, укажите `--folder "ПУТЬ"` перед `backup`. Папку для архива можно задать параметром `--to "ПУТЬ"` после команды. В Windows параметр `--portable-key` защищает ключ парольной фразой.

## Восстановление из зашифрованной копии

Откройте **10 Restore from backup**, затем **1 Check backup**. Укажите файл `.cwbackup` или нажмите Enter, чтобы взять последнюю локальную копию. На запросе ключа нажмите Enter, чтобы панель нашла его в локальной папке `backup-keys`. Если архив или ключ переместили либо переименовали, укажите путь к ключу явно.

- **2 Restore operator folder** восстанавливает папку оператора по новому пути. Откройте её через `COLDWIRE-Admin.cmd --folder "ПУТЬ"` в Windows или `bash COLDWIRE-Admin.sh --folder "ПУТЬ"` в Linux. Сохраните текущую папку, пока не проверите доступ из восстановленной.
- **3 Export A and B for recovery** выгружает архивы узлов, контрольные суммы, исходные адреса и интерфейсы в `network.json`, скрипт восстановления и версию панели из копии. Выберите закрытую папку на локальном диске. В выгрузке ключи хранятся в открытом виде.
- **4 Save a portable recovery key** сохраняет отдельный ключ, зашифрованный парольной фразой. Сделайте это, пока архив можно открыть в исходном профиле Windows. На компьютере восстановления укажите этот файл на запросе ключа. Парольную фразу храните отдельно.

Для восстановления узла подключите подготовленный диск в режиме rescue у провайдера. Используйте ту же версию и архитектуру ОС, имя внешнего интерфейса и сетевые адреса. На диске должны быть прежние системные зависимости, включая OpenSSH, nftables и conntrack, и учётная запись для SSH COLDWIRE. Если адреса VPS или имя интерфейса изменились, перед запуском обновите адреса в правилах экрана, настройках реле, SSH, панели и профилях.

Поместите скрипт, архив нужного узла и `SHA256SUMS` в одну папку в системе rescue. Выполните подходящую команду. Вместо `/mnt/server` укажите точку монтирования диска этого узла.

```sh
sudo python3 restore_backup.py exit --root /mnt/server
sudo python3 restore_backup.py entry --root /mnt/server
```

Сначала восстановите и загрузите B, затем A. Проверьте SSH через SPA и подключение по существующему VPN-профилю. Копия включает данные COLDWIRE и файлы служб. ОС, учётные записи и сетевые настройки провайдера берутся с подготовленного диска.

## Если что-то пошло не так

- Если установка оборвалась на настройке экрана, подождите до трёх минут, пока сработает откат неподтверждённого этапа. Перед повторной попыткой проверьте сообщение установщика и консоль провайдера. Подтверждённые правила сохраняются. Если потерялись ключи, используйте аварийную консоль.
- Если после перезагрузки не загрузились правила для внешнего интерфейса, восстановите через консоль провайдера рабочую копию `/etc/coldwire-lockdown/active.nft`. Перезагрузите узел и проверьте доступ через панель.
- Если на A не загрузились правила допуска SPA, восстановите `/etc/coldwire-access/active.nft` для новой установки или `/var/lib/coldwire-spa-pilot/pilot.nft` для пилотной. Перезагрузите узел и проверьте доступ.
- Если вход по SSH из панели не работает, проверьте правила у провайдера для UDP-порта SPA на A и выбранного SSH-порта. На B проверьте разрешение для IPv4 узла A. При сообщении о смене ключа SSH сверьте его в консоли провайдера.
- Если VPN не подключается, убедитесь, что установлено приложение COLDWIRE и выбран профиль из панели. Проверьте состояние обоих узлов и регистрацию устройства. В инструкции клиента описано, как сохранить журнал.
- Чтобы перенести панель на другой компьютер, скопируйте закрытую папку и укажите её путь через `--folder PATH`. В Linux задайте папке права `700`, а закрытому ключу `ssh` права `600`.

## Что проверено

Чистую установку на amd64 проверили на всех пяти версиях Linux. В каждой VM было одно vCPU и 1 ГиБ памяти. Проверки охватывали установку, закрытие исходного порта SSH, выдачу и отзыв профиля, откат по таймеру и после перезагрузки, а также обычную перезагрузку A. Скрипт запуска проверили на Windows 11 и всех пяти версиях Linux. На стенде с Debian 13 конвертированные клиентский и администраторский профили передавали трафик по туннелю. Контрольные суммы исходных файлов совпали.

На Debian 13 с пилотным SPA настройки и ключи административного допуска сохранились при потере правил внешнего интерфейса, даже со старой меткой `pilot-upgrade`. Для возврата доступа хватило восстановить правила через консоль и перезагрузить узел. Подтверждение правил очищает метку. [Отчёт стенда на английском](../pilot-upgrade-recovery.md)
